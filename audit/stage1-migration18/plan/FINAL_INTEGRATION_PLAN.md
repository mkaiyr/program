## 4. Технические риски

| № | Риск | Влияние | Снижение |
|---|---|---|---|
| R1 | Эмуляция Supabase создана по памяти; Storage, Edge, PostgREST-настройки (`db-max-rows`, кэш схемы), CORS не проверялись | Расхождение с Production | Staging-проект Supabase (B1); контракт-тесты на нём перед боевой раскаткой |
| R2 | Большая поверхность SECURITY DEFINER (~50 RPC) | Ошибка прав = утечка или порча данных | Автоматическая матрица прав (роль × функция × ожидаемый результат) после каждой миграции; `revoke` по умолчанию; единый шаблон проверки роли |

## 8. Этапы работ

Для каждого этапа: цель → зависимости → артефакты → тесты → критерии приёмки. Каждый этап заканчивается отчётом (до/после, журналы, результаты тестов) и остановкой до вашего разрешения. Общие правила SQL-этапов — как в `IMPLEMENTATION_PLAN_18_23.md` (pre-check → одна транзакция → `revoke` → `grant` → post-check → SQL-тесты в стиле `sql/tests` с `rollback` → снимок схемы до/после → журнал).

### Порядок и зависимости (редакция 2)

### Этап 6c. Миграция 25 — отчёты
- **Зависит от:** 19–24.

## 11. Правила работы на каждом этапе
1. Перед этапом — снимок состояния (`pg_dump --schema-only`, список объектов, хеши исходников, `git status`).

6. Демонстрационные и реальные данные не смешиваются; фиктивные рабочие данные не создаются.
