| `out_for_delivery` | `failed` | то же | причина обязательна; дальше — `void_order` и ручные складские операции (если приготовление началось, автовозврата нет) |
| `pending` | `failed` | то же | клиент отказался до отправки; причина обязательна |
| `delivered`, `failed` | — | — | конечные |

Самовывоз: записи доставки нет; завершение — штатный `set_order_status('completed')` из приложения.

| № | Проблема в плане | Исправление |
|---|---|---|

### 4.2. Формулы (предлагаются к утверждению; проверяются независимым пересчётом)

Определения. **Заказ в отчёте** — `confirmed_at is not null` и `voided_at is null`; период — по `sale_at`; часовой пояс Asia/Almaty для разбивки по дням.

| Показатель | Формула |
|---|---|
| `orders_count` | число заказов в отчёте |
| `dishes_revenue` | Σ `subtotal` |
| `service_total` | Σ `service_amount` (надбавка кассы) |
| `revenue` (ключ сохранён) | Σ (`subtotal` + `service_amount`) = Σ (`total` − `delivery_fee`) |
| `delivery_total` | Σ `delivery_fee` (в `revenue` не входит) |
| `gross_total` | Σ `total` |
| `average_check` | `revenue / orders_count`, округление 2 знака; 0 при пустом периоде |
| `voided_count`, `voided_total` | подтверждённые заказы с `voided_at`, Σ `total` (отклонённые и истёкшие до принятия — отдельный счётчик `web_rejected_count`) |
| `web_orders_count`, `web_revenue` | то же для `source = 'web'` |
| `cogs` (себестоимость продаж) | Σ по заказам отчёта чистого расхода: Σ(−`delta` × `unit_cost`) по движениям `sale`, `cancel`, `return` этих заказов |
| `void_loss_cost` | то же по аннулированным заказам: стоимость израсходованного и не возвращённого (учтена как потери, а не как себестоимость) |
| `gross_profit` | `revenue − cogs` (доставка и надбавка за обслуживание в «прибыли» учтены так: надбавка входит в `revenue`; расходы на доставку и зарплаты **не** учитываются) |
| `margin_percent` | `gross_profit / revenue × 100`, при `revenue = 0` — пусто |
| `cogs_coverage` | доля `revenue` по строкам, у блюд которых на момент продажи была технологическая карта |
| `revenue_without_recipe` | Σ `line_total` позиций без списания по карте |

Складские отчёты:

| Отчёт | Формула |
|---|---|
| Остаток и оценка | `stock`, оценка = `stock × purchase_price` (по текущей цене; подпись «оценка») |
| Движение за период | на начало = Σ `delta` до начала периода + начальный остаток; приход (`receipt`), расход (`sale`), возвраты (`cancel`, `return`), потери (`loss`), корректировки (`count`); на конец = начало + Σ; **тождество `начало + Σ = конец` проверяется тестом по каждому продукту** |
| Поступления | Σ `total` подтверждённых документов по `confirmed_at` (дата документа показывается отдельно) |
| Потери | Σ (−`delta` × `unit_cost`) по `loss` и отрицательным `count` |
| Инвентаризации | недостача и излишек в количестве и стоимости, по документам |
| Интернет-заказы и доставка | `web_orders_count`, `web_revenue`, `delivery_total`, разбивка по статусам доставки, `failed`, отклонённые |

Приёмка 25: суммы отчётов совпадают с независимым пересчётом (скрипт на тестовых данных); ожидающие не в продажах; `delivery_total` не входит в `revenue`; тождество движений по каждому продукту; период > 366 дней отклоняется, как в `admin_report`.

## 5. Матрица безопасности

### 5.1. Установленные факты (из БД)
- Для `anon` сейчас доступна единственная функция `employee_login_email`; `PUBLIC` не имеет EXECUTE на функции проекта; 46 из 63 функций доступны `authenticated`.
