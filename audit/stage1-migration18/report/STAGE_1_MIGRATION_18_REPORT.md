## 6. Отклонения от плана и найденные проблемы (честно)
1. **Найдена неточность самой миграции, исправлена поправкой 18a.** Тест группы 3 показал: если слаг занят другой категорией, триггер сообщал `SLUG_RESERVED`, а должен — `SLUG_TAKEN` («зарезервирован» — только использованный ранее и сейчас ничем не занятый слаг). Исправление — `CREATE OR REPLACE` одной функции `_slug_guard()` (права сохраняются, проверено): файл `18a_slug_guard_fix.sql`, применён к базе сразу после первого применения. В итоговый файл `18_unified_catalog.sql` внесено то же определение; **применённый первоначальный вариант сохранён** как `18_unified_catalog.applied_v1.sql`; различие между ними — только эти строки функции (проверено `diff`), тело функции в базе совпадает с файлом. Чистая «единым файлом» проверка на пустой базе не выполнялась (создавать отдельную базу не разрешено): на сегодня состояние = `applied_v1` + `18a`.
2. **Ошибки в моих тестах (не в миграции):** тип `jsonb_agg('bun')` без приведения (исправлено в тесте).
3. **Регрессия старых проверок:** они требуют уже существующих администратора, кассира, кухни, бара и позиции меню (на пустой базе — отказ предусловия). Я прогонял их в обёртке: временное заполнение + проверка в одной транзакции, итоговый `rollback` откатывает всё. Сначала проверка 13 стала падать после миграции с `invalid salt`; причина — **не миграция**: условие проверки сравнивает `crypt()` по строкам `auth.users`, и PostgreSQL вправе вычислить его раньше фильтра по `id`, споткнувшись о мои временные учётные записи с «паролем» `x` (не bcrypt-хеш). Исправил свой временный набор (настоящие bcrypt-хеши) — проверка 13 проходит 3 раза подряд. Что именно переключило план запроса, не выясняла (вероятная причина — смена статистики после миграции); важно, что старые проверки не изменялись.
4. **Особенности окружения:** `inet_server_port()` по сокету даёт NULL (порт проверялся через `current_setting`); zsh не разбивает переменную с аргументами команды — две мои первые попытки предусловий упали до любых изменений и были повторены через скрипт-обёртку.
5. **Не проверялось (вне области этапа):** Storage-бакеты и их политики (только staging, замечание F23), фактическое поведение настоящего Supabase Auth (эмуляция по памяти — R1), сайт и приложение (к базе не подключались).
