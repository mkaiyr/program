# Архитектура

## Общая схема

```
Tkinter (main.py) ──► db.Database ──► supabase-py ──► Supabase
   экраны ui_*.py       (AppError)        PostgREST (таблицы под RLS, RPC)
                                          Auth (email + пароль)
```

- Клиент — настольное приложение с **публичным** ключом Supabase. Секретный ключ и
  `service_role` отклоняются при чтении `config.ini` (`config.py`).
- **Чтение** — прямые `select` к таблицам, видимость ограничивает RLS.
- **Запись** — только RPC-функции `SECURITY DEFINER` с `search_path = ''`. Прав `INSERT/UPDATE/DELETE`
  на таблицы у клиентских ролей нет.
- Ошибки сервера приходят как `message` исключения (`NAME_TAKEN`, `MENU_CHANGED`, …) и переводятся в
  понятный текст в `db.RPC_ERRORS`; `AppError.code` (`auth`, `network`, `invalid`, `forbidden`,
  `order_changed`, `menu_changed`) определяет реакцию экрана.

## Модули

| Файл | Назначение |
|---|---|
| `main.py` | Окно `App`, экран входа, выбор главного экрана по роли |
| `db.py` | Все обращения к Supabase; проверка ввода; константы статусов и переходов |
| `search.py` | Поиск по коду (полному или началу) и подстроке названия, без учёта регистра |
| `ui_theme.py` | Цвета, шрифты, стили ttk, карточки, `ScrollFrame` |
| `ui_login.py` | Вход по коду сотрудника и паролю, экранная клавиатура |
| `ui_order.py` | Касса: каталог, поиск, корзина, оформление заказа |
| `ui_orders.py` | Окно «Заказы»: список, состав, выдача, принудительная готовность (админ) |
| `ui_admin.py` | Управление меню |
| `ui_kitchen.py` | `KitchenFrame` (кухня) и `BarFrame` (бар): заказы станции, автообновление, звук |
| `ui_kitchen_menu.py` | Вкладка «Меню» кухни: наличие блюд, фильтры |

## Роли и маршрутизация

После входа `db.sign_in` читает профиль сотрудника (`profiles`) под RLS и пропускает только
активных сотрудников с ролью из `ALLOWED_ROLES`. `App.show_main` открывает:

| Роль | Экран | Источник заказов | Что меняет |
|---|---|---|---|
| `cashier` | `OrderFrame` + окно «Заказы» | таблицы `orders`/`order_items` (свои заказы, RLS) | создаёт заказ (`create_order`), выдаёт (`set_order_status → completed`) |
| `admin` | `OrderFrame` + «Заказы» + «Управление меню» | все заказы (RLS) | меню (`admin_*`), выдача, `admin_force_order_ready` |
| `kitchen` | `KitchenFrame` | `kitchen_orders()` — только кухонные позиции, без цен | `set_station_status(…, 'kitchen', …)`, наличие (`kitchen_set_menu_item_available`) |
| `bar` | `BarFrame` | `bar_orders()` — только барные позиции, без цен | `set_station_status(…, 'bar', …)` |

Права окончательно проверяет сервер; скрытые кнопки в интерфейсе — только удобство.

## Статусы заказа и станции

Каждая позиция заказа относится к станции (`order_items.station` — снимок `menu_items.station`
на момент продажи). Для каждой станции заказа есть строка `order_stations` со своим статусом:

```
станция:  accepted ──► preparing ──► ready          (kitchen / bar — только своя станция)
заказ:    вычисляется сервером из станций:
          все станции ready          → ready
          хотя бы одна начала        → preparing
          иначе                      → accepted
          ready ──► completed        (кассир — свои заказы, администратор — любые)
```

- Готовый напиток не делает готовым смешанный заказ «еда + напиток».
- Обычным переходом нельзя выставить «Готовится»/«Готов»; администратор может только явно
  отметить заказ готовым целиком (`admin_force_order_ready`, с подтверждением в интерфейсе).

## Фоновые запросы и потоки

Сетевые запросы не выполняются в главном потоке Tk. Каждый экран использует одну схему:

```
_run(task, on_ok, on_err)
  └─ поток: task() ──► deliver(callback, value) ──► root.after(0, _finish, …)
                                                       └─ главный поток: _finish → callback
```

- Флаг `busy` — одновременно не более одного запроса на экран; кнопки на время запроса отключены.
- Результат передаётся через **корневое окно**, а `_finish` игнорирует его, если экран или окно
  уже закрыты (`closed`, ставится в `destroy()`) — выход из аккаунта во время запроса безопасен
  на экранах кухни и бара и в окнах «Заказы» и «Управление меню». Касса (`OrderFrame`) не даёт
  выйти, пока идёт её собственный запрос.

## Автообновление и звук (кухня, бар)

- Таймер `after(AUTO_REFRESH_MS = 7000)`; если идёт другой запрос — откладывается до следующего
  срабатывания. Таймеры отменяются в `destroy()`.
- Новые заказы определяются по ID (`SeenOrders`, не более 5000 ID): первая успешная загрузка
  только запоминает текущие заказы; затем один сигнал на обновление, в котором появились новые ID.
  Смена статуса, повторная загрузка и повторное появление заказа сигнала не дают.
- Звук: `winsound.MessageBeep` на Windows, `bell()` Tk на остальных системах; ошибка звука
  не мешает работе.
- Ошибка автообновления — строка статуса и `logging.warning`, без всплывающих окон; истёкшая
  сессия по-прежнему ведёт к выходу.
- Карточки перерисовываются только при изменении данных; строка поиска и прокрутка сохраняются.

## Производительность

Поиск работает локально по загруженному списку. Касса рисует не больше 60 плиток, вкладка
«Меню» кухни — не больше 100 карточек; при большем числе показывается подсказка уточнить поиск.
