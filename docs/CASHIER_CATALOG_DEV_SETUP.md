## 2. Рекомендованный вариант: новый отдельный кластер (максимальная изоляция)
Почему не существующие серверы: системный сервер (5432) — чужие данные и неизвестный доступ; стенд (54322) хранит ценные базы и его запуск меняет состояние процессов. Новый кластер **не затрагивает ничего существующего**: свой каталог, свой порт, только unix-сокет (без сетевого доступа), свой пользователь.

- **Сервер:** новый экземпляр PostgreSQL 17.2 из `/Library/PostgreSQL/17/bin`, каталог данных `~/cashier_catalog_dev_pg/data`, порт **54323**, `listen_addresses = ''` (только сокет `~/cashier_catalog_dev_pg/run`).
- **Пользователь БД:** новый суперпользователь `catalog_dev_admin` (только внутри этого кластера; пароля нет, вход только через локальный сокет пользователя `dom`).
- **База:** `cashier_catalog_dev`, кодировка UTF8.

## 3. Точные команды (выполнить только после подтверждения)
```bash
PGBIN=/Library/PostgreSQL/17/bin
ROOT="$HOME/cashier_catalog_dev_pg"

# Перед началом — повторная проверка, что ничего не занято (должно ничего не вывести)
test -e "$ROOT" && echo "СТОП: каталог уже существует" ; lsof -nP -iTCP:54323 -sTCP:LISTEN

# 1) Каталоги
mkdir -p "$ROOT/run" && chmod 700 "$ROOT"

# 2) Новый кластер (никакие существующие данные и настройки не затрагиваются)
"$PGBIN/initdb" -D "$ROOT/data" -U catalog_dev_admin -E UTF8 --locale=en_US.UTF-8 --auth-local=trust --auth-host=reject

# 3) Запуск ТОЛЬКО на сокете, порт 54323, журнал внутри каталога
"$PGBIN/pg_ctl" -D "$ROOT/data" -l "$ROOT/server.log" -w \
  -o "-p 54323 -c listen_addresses='' -c unix_socket_directories='$ROOT/run'" start

# 4) Создание базы
"$PGBIN/createdb" -h "$ROOT/run" -p 54323 -U catalog_dev_admin -E UTF8 cashier_catalog_dev

# 5) Проверка
"$PGBIN/pg_isready" -h "$ROOT/run" -p 54323
"$PGBIN/psql" -h "$ROOT/run" -p 54323 -U catalog_dev_admin -d cashier_catalog_dev -XAtc "select current_database(), version()"
```
Остановка и удаление (удаление — только по отдельной команде владельца, и только этого каталога):
```bash
"$PGBIN/pg_ctl" -D "$HOME/cashier_catalog_dev_pg/data" stop            # остановка
# rm -rf "$HOME/cashier_catalog_dev_pg"                                 # удаление — НЕ выполнять без отдельного подтверждения
```

## 4. Какие операции будут выполнены
1. Создан каталог `~/cashier_catalog_dev_pg` (около 40 МБ).
2. Инициализирован новый кластер (одна команда `initdb`), без изменений существующих кластеров и их конфигурации.
3. Запущен один новый процесс `postgres` (порт 54323, только сокет).
4. Создана одна база `cashier_catalog_dev`.
5. **Ничего больше** на этом шаге: ни миграций, ни ролей Supabase, ни данных.

## 5. Следующий шаг после создания (отдельное подтверждение)
Эмуляция Supabase (схема `auth`, роли `anon`/`authenticated`/`service_role`, `auth.uid()`) — теми же скриптами, что использовались для проверки миграций 11–16 (`~/cashier_pgrst_test/sql_emulation`, копия, **исходные файлы не изменяются**) → применение **копий** миграций 01–16 из `sql/` в этой новой базе → пред-/пост-проверки → черновики 18–23 (после согласования схемы) → SQL-проверки по векторам `docs/contracts/inventory_vectors.json`. Приложение и сайт к этой базе не подключаются; Production не затрагивается.
