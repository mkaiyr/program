# Разработка

## Окружение

- Python 3.12 (Tkinter входит в стандартную поставку python.org).
- Зависимости: `requirements.txt` (`supabase>=2.33,<3`).

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp config.example.ini config.ini
```

`config.ini` — только URL проекта и **публичный** ключ. Файл в `.gitignore`; секретные ключи
приложение отклоняет. Для разовых административных действий (`reset_cashier_password.py`)
секретный ключ вводится при запуске и нигде не сохраняется.

## Проверки

```bash
python3.12 -m py_compile *.py tests/*.py
python3.12 -m unittest discover -s tests -v
```

| Файл | Что проверяет |
|---|---|
| `tests/test_status_access.py` | статусы и переходы, роли, экран кухни, окно «Заказы» |
| `tests/test_menu_availability.py` | наличие блюд, каталог кассы, новая вкладка «Меню» кухни |
| `tests/test_menu_codes.py` | поиск, коды позиций, текст миграции 07, управление меню |
| `tests/test_search_panels.py` | поиск в кассе и меню кухни, лимиты отрисовки, скорость на 1000 позиций |
| `tests/test_bar_stations.py` | роль `bar`, станции, экран бара, миграция 08 (включая разбор `profiles_role_check`) |
| `tests/test_station_refresh.py` | автообновление 7 с, новые заказы и звук, ошибки сети, закрытие во время запроса |

Тесты не подключаются к Supabase: используются заглушки `Database` и источников заказов;
проверки миграций — статический разбор SQL (сам SQL локально не выполняется).

Особенности:

- `tests` — не пакет; запускать через `discover -s tests` (модули импортируют `_tk` из папки тестов).
- Все UI-тесты используют одно окно Tk (`tests/_tk.py`): второй `tk.Tk()` на macOS вешает процесс.
- Звук в тестах подменяется (`ui_kitchen.play_alert`).

SQL-проверки `sql/tests/*_checks.sql` выполняются в Supabase SQL Editor на **тестовом** проекте;
каждая работает в транзакции с `rollback` и ничего не сохраняет. Порядок — в [DATABASE.md](DATABASE.md).

## Правила

- Изменения данных — только через RPC с проверкой `auth.uid()` и активной роли; не выдавать
  клиентам права на таблицы и не ослаблять RLS ради интерфейса.
- Новые функции: `SECURITY DEFINER` только при необходимости, всегда `set search_path = ''`,
  `revoke all … from public, anon`, `grant execute … to authenticated` — только нужным ролям.
- Миграции — новыми файлами с следующим номером; применённые миграции не переписывать.
  Каждая миграция — одна транзакция, предусловия проверяются до изменений, повторный запуск безопасен.
- Сетевые запросы — только в фоновом потоке через `_run`; виджеты — только в главном потоке.
- Не коммитить `config.ini`, `.env`, `.mcp.json`, ключи и выгрузки реальных данных.

## Работа с базой

- Миграции не применяются автоматически — только вручную, сначала на тестовом проекте.
- На production — только чтение, пока владелец отдельно не подтвердил применение миграции.
- Supabase MCP (`.mcp.json`, локальный файл) настроен с `read_only=true`; подключается
  через `/mcp` в интерактивной сессии Claude Code. Даже в режиме чтения не запрашивать строки
  таблиц с персональными данными и заказами без необходимости — достаточно схемы и метаданных.
