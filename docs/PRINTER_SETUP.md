# Подключение и проверка термопринтера 80 мм (macOS и Windows)

> Эта инструкция подготовлена без доступа к физическому принтеру: программа проверена тестами, но **печать на реальном устройстве ещё ни разу не выполнялась**. Выполните шаги ниже на настоящем принтере и сверьте результат с чек-листом в конце.

Приложение печатает чек **картинкой** (растром, команды ESC/POS `GS v 0`), чтобы казахские буквы қ ұ ү ғ ң і ә ө не зависели от кодовых страниц принтера. Принтер должен понимать ESC/POS-растр (почти все чековые принтеры 80 мм: Epson TM-серии и совместимые — Xprinter, Rongta, Sunmi, POS-80 и т. п.).

## 0. Подготовка (одинаково для macOS и Windows)
1. Python 3.12 и зависимости: `pip install -r requirements.txt` (нужен **Pillow**; без него печати нет, остаётся текстовый предпросмотр).
2. Загрузите в принтер бумагу 80 мм, включите принтер. Узнайте ширину печати: у большинства моделей 80 мм это **576 точек** (72 мм), у части — **512**. Если не знаете, начните с 576 и смотрите на результат (см. «Если что-то не так»).
3. Выберите способ подключения:
   - **Сеть (Ethernet/Wi-Fi) — рекомендуется.** Не требует драйверов, одинаково работает на macOS и Windows.
   - **USB** — через принтер, установленный в системе (режим `system`).

## 1. Способ «сеть» (macOS и Windows)
1. Узнайте адрес принтера: выключите принтер, зажмите кнопку подачи бумаги (Feed), включите — принтер напечатает страницу самодиагностики с IP-адресом (у многих моделей по умолчанию 192.168.123.100 или получен по DHCP). Порт RAW обычно **9100**.
2. Проверьте, что компьютер видит принтер в одной сети:
   - macOS (Терминал): `nc -vz 192.168.1.50 9100` → должно быть «succeeded».
   - Windows (PowerShell): `Test-NetConnection -ComputerName 192.168.1.50 -Port 9100` → `TcpTestSucceeded : True`.
3. Откройте `config.ini` и добавьте (подставьте свой адрес; существующую секцию `[supabase]` не трогайте):
   ```
   [printer]
   mode = network
   host = 192.168.1.50
   port = 9100
   width_dots = 576
   cut = yes

   [receipt]
   cafe_name = Кафе Бистро
   ```

## 2. Способ «USB» через систему (режим `system`)
### Windows
1. Подключите принтер по USB и установите драйвер производителя. Если драйвера нет — добавьте принтер вручную: «Параметры → Принтеры и сканеры → Добавить → Нужный принтер отсутствует → Локальный принтер → порт USB001 → Производитель **Generic**, принтер **Generic / Text Only**».
2. Узнайте **точное имя** принтера: PowerShell → `Get-Printer | Select-Object Name,DriverName,PortName`.
3. Либо `python print_test.py --list` покажет имена, которые видит приложение.
4. В `config.ini`:
   ```
   [printer]
   mode = system
   name = POS-80          ; ровно как в списке, с регистром и пробелами
   width_dots = 576
   ```
   Данные отправляются драйверу в режиме RAW (через Windows API); драйвер «Generic / Text Only» их не искажает.
### macOS
1. Подключите принтер по USB. «Системные настройки → Принтеры и сканеры → + (Добавить)». Для сырых команд нужна очередь без фильтров: самый простой путь — сетевой режим (раздел 1). Если нужен именно USB, в Терминале:
   - `lpinfo -v` — найдите адрес устройства (вид `usb://...`), при необходимости через `sudo`.
   - `sudo lpadmin -p POS80 -E -v "usb://АДРЕС_ИЗ_СПИСКА" -m raw` — создаст «сырую» очередь (на новых версиях macOS ключ `-m raw` может выдать предупреждение об устаревании; если очередь не создаётся — используйте сетевой режим).
2. `lpstat -e` — в списке должно быть имя очереди (например, `POS80`), либо `python3 print_test.py --list`.
3. `config.ini`:
   ```
   [printer]
   mode = system
   name = POS80
   width_dots = 576
   ```

## 3. Проверка без приложения и без базы — `print_test.py`
Из папки приложения:
```
python3 print_test.py --preview test.png     # картинка того, что будет напечатано (принтер не нужен)
python3 print_test.py --file test.bin        # записать команды в файл (принтер не нужен)
python3 print_test.py                        # напечатать тестовый чек на принтер из config.ini
python3 print_test.py --width 512            # то же с шириной 512 точек
python3 print_test.py --list                 # принтеры, видимые системе
```
Тест **не создаёт заказ**, не использует базу и не меняет журнал печати этого компьютера. Если `print_test.py` напечатал чек, приложение напечатает так же.

Ручная проверка файла на macOS (если режим `system` не печатает): `lp -d POS80 -o raw test.bin`.

## 4. Проверка в приложении
1. Запустите приложение, войдите кассиром или администратором, откройте «Заказы», выберите заказ.
2. Нажмите **«Чек…»** — откроется предпросмотр. Нажмите **«Печать»**.
3. Нажмите «Чек…» у того же заказа ещё раз: кнопка должна называться **«Повторная печать»**, приложение спросит подтверждение, а на бумаге в шапке будет «*** ПОВТОРНАЯ ПЕЧАТЬ (копия 1) ***».
4. Выключите принтер (или отсоедините кабель) и нажмите «Печать»: должно появиться понятное сообщение об ошибке, заказ при этом остаётся в списке без изменений, а повторная попытка после включения принтера печатает чек как первый.

## 5. Чек-лист приёмки на бумаге
- [ ] Все строки видны целиком, текст не обрезан ни слева, ни справа.
- [ ] Видны все казахские буквы `қ ұ ү ғ ң і ә ө Қ Ұ Ү Ғ Ң І Ә Ө` и русский текст без искажений; знаки `₸` и `№` читаются.
- [ ] Линии-разделители сплошные, шрифт чёткий (не расплывается).
- [ ] Чек обрезается после последней строки, пустого места не слишком много.
- [ ] Итого совпадает с итогом заказа в приложении; позиции, количество и цены верны.
- [ ] Внизу написано «Чек не является фискальным документом».
- [ ] Повторная печать помечена как копия; печать не создала новый заказ и не изменила статус.

## Если что-то не так
| Симптом | Что сделать |
|---|---|
| Чек обрезан справа или слева | уменьшить `width_dots` (576 → 512) |
| Слева/справа большие пустые поля | увеличить `width_dots` до 576 (кратно 8, максимум 832) |
| Печатает «мусор» из символов или ничего | принтер не понимает растр ESC/POS или канал не «сырой»: сеть (RAW 9100) вместо USB-очереди; проверьте режим принтера (ESC/POS) в самодиагностике |
| «Принтер не найден» | имя в `config.ini` должно совпадать с `python3 print_test.py --list` |
| «Не удалось подключиться» | принтер выключен, другая сеть, неверный IP/порт; проверьте командами из раздела 1 |
| Бумага не обрезается | поставьте `cut = no` (нет резака) или проверьте, что модель поддерживает команду обрезки |
| Очень длинный чек обрывается | печатайте чек порциями меньше; сообщите точное число позиций |

## Ограничения
- Журнал печати **локальный** (файл `~/.bistro_cashier/print_log.jsonl` на этом компьютере), он не общий между кассами: «повторная печать» определяется только по этому компьютеру.
- Чек строится из данных списка «Заказы» на момент его последнего обновления; перед печатью важного чека нажмите «Обновить».
- Способа оплаты и скидки в заказе нет в базе, поэтому на чеке они не печатаются. Менять базу ради них нельзя без вашего разрешения.
- Фискализация (онлайн-касса и оператор фискальных данных) не реализована.
