# Контракт публичного каталога (сайт ⇄ общая система)

Формат тот же, что сейчас у `docs/data/menu.json` сайта; серверная функция `public_menu()` (в будущем) обязана отдавать именно его. Проверяет формат `catalog-source.js` на сайте (`validateCatalog`): неверные данные отклоняются, а не «исправляются».

```json
{
  "schema": 1,
  "categories": [{ "id": "burgers", "name": "Бургеры", "sort": 1 }],
  "dishes": [{
    "id": "cheeseburger",              // неизменяемый слаг (menu_item_public.slug); латиница, цифры, дефис
    "name": "Чизбургер",               // 1–100 знаков
    "category": "burgers",             // id существующей категории
    "price": 2290,                     // целое число тенге > 0 (сервер хранит numeric, на сайт — целое значение, которое он сам считает ценой)
    "description": "…", "weight": { "value": 260, "unit": "г" },
    "ingredients": ["bun", "beef_patty"],   // идентификаторы справочника состава (для аллергенов), не технологическая карта
    "recommended": true, "sort": 1,
    "available": true,                 // можно заказать сейчас (is_available)
    "active": true,                    // необязательно; false — скрыто из публичного меню (в публичный ответ не попадает)
    "photo": { "file": "cheeseburger.webp", "thumb": "cheeseburger-thumb.webp", "alt": "Чизбургер", "width": 1200, "height": 900 }   // или null
  }]
}
```
Правила: сервер отдаёт только опубликованные и не архивные блюда; закупочные цены, коды станций и технологические карты в ответ не входят; цена и доступность всегда серверные, сайт не доверяет цене, пришедшей из браузера; история заказов хранит снимки названия и цены на момент покупки.
